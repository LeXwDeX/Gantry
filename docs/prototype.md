# 界面原型说明

> 状态：原型 v0.2（2026-10-24），已按[交互评审](reviews/2026-10-24-ux-review.md)修订。**界面中全部为示例数据**。可交互原型：[Gantry 控制台原型](https://claude.ai/artifact/AFWjX1VuDkwHvxfNLC5t29)（私有链接，所有者分享后他人才能打开），源码在 [prototype/](../prototype/)。本文是原型的文字版规格，`desktop-ui` 与 `mobile` 按本文实现。

## 1. 设计原则

| 原则 | 落地 |
| --- | --- |
| 主对话是核心（D-10） | 工作区中栏默认是对话视图；空项目也保留对话与输入区 |
| 配置与工作分离（D-09、I7） | 模型、预算模板、策略只在设置页；工作区只有运行状态和"控制"（暂停、放弃、升档决定） |
| 工程化、现代、紧凑（D-11） | 深色石墨底、编号与分支用等宽字体、12–13px 正文、8px 网格 |
| 无头像，边框区分 agent（D-12） | agent 气泡 2px 边框为种类色，气泡内左上角有种类文字 |
| 手机只对话（D-11） | 手机端只有一个对话屏 |
| 上下文显式 | 选中某项只影响检视器；消息发往哪里由输入区的 `@` 决定 |
| 签名只在审批单 | 任何地方的审批入口都只"打开审批单"，签名只能在审批单里完成 |

### 1.1 颜色与记号

颜色从不单独表达含义：每种状态都同时有文字。

| 用途 | 颜色 | 记号 |
| --- | --- | --- |
| 运行中 | 蓝 `#58A6FF` | 圆点 + 状态文字 |
| 后台静默处理中（自愈） | 中性灰 `#8B949E` | 圆点 +"自愈中" |
| **需要你** | 黄 `#E3B341` | 黄底药丸"! 需要你 · <类型>"，不依赖 agent 颜色 |
| 完成 / 通过 | 绿 `#3FB950` | 圆点 + 文字 |
| 空闲 / 暂停 / 放弃 | 暗灰 `#6E7681` | 圆点 + 文字 |
| 失败且无人处理、缺规格 | 橙 `#F0883E` | 只在这两种情况用橙色 |
| agent · 大脑 | 紫 `#A371F7` | 气泡边框 + "大脑" |
| agent · 干活 | 青 `#39C5CF` | 气泡边框 + "干活" |
| agent · 打杂 | 灰 `#8B949E` | 气泡边框 + "打杂" |
| 档位徽标 | 单色 | 灰框白字，不占用状态色和 agent 色 |

## 2. 桌面端 · 工作区

| 区域 | 位置 | 宽度 | 内容 |
| --- | --- | --- | --- |
| 顶栏 | 顶部通栏 | — | Logo · 项目 tab（带"需要你"数字徽标）· + · 示例数据 · 本机角色 · 连接状态 · 需要你 · n · 设置 |
| 左栏 | 左 | 约 240px | 项目信息、进行中 Issue、进行中 PR、工作树、最近完成 |
| 中栏 | 中 | 弹性 | 视图切换：对话（默认）/ 关系地图 / 工作树 |
| 检视器 | 右 | 约 300px | 选中项的状态、需要你、交付阶段、当前阶段的图、后台守护 |
| 状态栏 | 底部通栏 | — | 连接状态、最近一条事件（可点）、运行中沙盒数 |

工作区整体占满窗口，各栏内部滚动，输入区始终可见。窄屏时三栏依次堆叠。每个项目各自保存：视图、选中项、草稿、`@` 上下文、档位上限、过滤开关；切换项目再切回时恢复。

### 2.1 顶栏

| 元素 | 行为 | 数据 |
| --- | --- | --- |
| 项目 tab | 切换项目；有待处理事项时显示黄色数字徽标 | `GET /v1/projects` + 各项目 open 的 InboxItem 数 |
| 本机 · 角色 | 显示当前设备角色：审批设备 / 操作设备 / 只读设备 | 当前设备 |
| 连接状态 | 一个指示：已连接 / 连接中断 · 重连中（合并 mTLS 与事件流状态） | 事件流心跳 |
| 需要你 · n | **全部项目**的 open 事项数；点击打开浮层，按项目列出事项，每项可直接操作或跳转 | `inbox` |
| 设置 | 以全屏浮层打开设置，不卸载工作区（返回后草稿和选中项都在） | — |

### 2.2 左栏

- 项目信息：`owner/repo`、项目名、默认上限、默认分支、"项目设置"链接（打开设置浮层的项目页）。
- 进行中 Issue / PR / 工作树：排序为 需要你 → 运行中 → 其他；超过 5 条折叠为"显示全部（n）"；标题截断时悬停显示全文。
  - 需要你的条目右侧显示"! 需要你"药丸；PR 没有待办时显示 CI 结果（CI 颜色只表示 CI 结果，与交付状态无关）。
- `main` 基线：点击后检视器显示分支保护、最近 CI、基于它的工作树数。
- "从分支开始任务…"：把输入区上下文设为该分支并聚焦输入框（不提供单独"新建工作树"，工作树总是属于某个交付）。
- 最近完成：已合并或已放弃的交付移到这里。

### 2.3 中栏 · 对话（默认视图）

**消息**

| 类型 | 表现 |
| --- | --- |
| 用户消息 | 右对齐蓝底气泡；下方显示 `@上下文 · 上限 X · 时间`，离线时附"待发送" |
| agent 消息 | 左对齐深底气泡，2px 种类色边框；气泡内第一行是种类文字，需要人时紧跟"! 需要你 · 类型"药丸 |
| 后台事件 | 一行：圆点 + 时间 + 摘要，可点击在检视器打开；**连续多条折叠**为"后台处理了 n 件事 ▸"，点开展开 |
| 上次查看分隔线 | 黄色分隔线"上次查看 hh:mm 之后"，下面紧跟打杂 agent 生成的"离开期间摘要"卡，每项可点 |

**气泡内附件**

| 附件 | 规则 |
| --- | --- |
| 执行计划卡 | 标题 + "● 实时"；步骤随事件实时更新 |
| 审批卡 | 显示"合并 PR #9 @ a1b2c3d"和审批的实时状态（待签名 / 已签名 / 已失效 / 已拒绝）；只有待签名时才有"审阅并签名…"按钮，它只打开审批单 |
| 升档卡 | 说明原因 + [升到 X 并继续] [保持当前，缩小范围] [放弃]；处理后变为"已处理：…" |
| 二选一 | 直接给按钮（如 [改为修复] [维持驳回]），不要求用户回复约定的词 |
| 引用 chip | `#5`、`PR #9`、分支名；点击只在检视器中查看，**不改变**输入区上下文 |
| 回复 | 气泡右下角"回复"：把输入区上下文设为该消息所属交付并聚焦输入框 |

**输入区**

- 多行输入框；`⌘↵`（macOS）/ `Ctrl+Enter`（Windows）发送；输入法组合中按回车不发送。
- `@ 上下文 ▾` 按钮：打开选择器（全项目 + 进行中的 Issue / PR / 工作树），可用 × 清除。**默认"全项目"，每次发送后复位。**
- 档位**上限**选择器：标签"上限"，旁边显示"≤ X"；默认是项目默认上限，`@` 已有交付时显示该交付的上限，每次发送后复位；方向键在选项间移动；悬停显示该档做什么；None 档提示"只问答，不建交付"。
- 当 `@` 的交付已有上限而用户改了上限时，输入区上方提示"PR #7 上限 Max → High；已触发的闸门不撤销"。文字里写的档位与选择器冲突时以选择器为准，agent 回执复述实际生效的上限。
- 只读设备：输入框与发送禁用，占位文字"此设备为只读"。离线时发送按钮变为"稍后发送"。
- 空项目：在对话视图中显示空态卡（描述一个任务 / 从已有 Issue 开始 / 新建 Issue），输入区照常可用。

### 2.4 中栏 · 关系地图

- 三列：Issue → Pull Request → 工作树 / 沙盒。节点卡：状态点、编号、档位徽标、状态或"! 需要你"、标题。
- 连线：实线 = closes / 分支；虚线 = refs 或"尚未开 PR"直连；橙色虚线 = 缺规格（PR 无关联 Issue）。
- 选中节点：**只高亮它所属的交付单元**（按 closes / 分支 / 直连边计算），refs 关系半透明保留；其余淡化。
- "只看需要你"过滤开关。
- 布局在实现时改为自动布局；节点很多时按 Milestone 分组（原型使用固定行）。

### 2.5 中栏 · 工作树

表格：工作树、关联（Issue / PR）、沙盒、写权持有者（前台 agent / 后台自愈 / 后台 review / —）、状态。名称列是按钮，可用键盘聚焦。

### 2.6 检视器

分工：**对话负责"发生了什么 + 需要你"，检视器负责"现在是什么状态 + 能做什么"**；两边出现的"需要你"是同一个上报项，处理后同时消失。

| 区块 | 内容 |
| --- | --- |
| 头部 | 编号、类型、状态（需要你时为黄色）；标题；"上限 X · 实际 Y"及自动加码原因；交付内的关联链（如 `#4 → PR #9 → feat/mtls-pair`）；refs 关系单独一行"相关：PR #8（refs #4）" |
| 操作 | [在对话中引用]：切到对话、设好上下文、聚焦输入框；[⋯]：暂停 / 继续、重试失败节点、放弃交付…（确认框写明会关闭哪个 PR、保留哪个分支） |
| 需要你 | 该交付所有 open 的上报项，每项带操作按钮 |
| 交付阶段 | 7 段：规格、计划、实现、提出、评审、合并、关闭；已完成绿、当前强调色、未到灰、**跳过的阶段画斜纹并写"跳过"** |
| 当前阶段的图 | 只列当前阶段的节点；合并阶段改为"合并闸门"清单 |
| 后台守护 | 守护处理过的事项与处置方式 |

只读设备上，操作按钮禁用。

### 2.7 审批单（唯一能签名的地方）

右侧抽屉，由任意"审阅并签名…"打开。

| 内容 | 说明 |
| --- | --- |
| 动作 | 如"合并（squash）" |
| 仓库、PR | `LeXwDeX/gantry`、`#9 · main ← feat/mtls-pair` |
| head SHA | 完整 40 位，等宽，可复制 |
| 改动 | 文件数、增删行数、文件列表；命中策略的文件高亮并注明原因（如"auth 路径"）；"在 GitHub 上查看此 SHA 的 diff"链接 |
| 合并闸门 | 必需 checks @SHA、GitHub review（未满足时给"去 GitHub 上 approve"）、merge queue、Gantry 签名 |
| 有效期 | 签名有效期 |
| 签名 | "用 Touch ID / Windows Hello 签名批准"；系统验证提示里显示 `merge LeXwDeX/gantry#9 @ a1b2c3d` |

规则：

- 打开审批单时向服务端取最新状态；签名载荷使用审批单上显示的 SHA，服务端发现 head 已变就拒绝。
- 以下情况禁用签名并写明原因：连接中断；本机不是审批设备（提示去哪台设备签）；GitHub 侧闸门未满足；审批已不在待签状态。
- 签名后，审批卡依次显示：已签名 · 排队 merge → 已合并 → Issue 已关闭 · 交付完成；对话追加对应事件行。
- 新推送使审批失效时，所有入口显示"已失效（旧 SHA → 新 SHA），重新评审中"，按钮消失。
- "拒绝"把交付退回评审。

### 2.8 状态与异常

| 情况 | 表现 |
| --- | --- |
| 连接中断 | 顶栏与状态栏变灰"重连中"；对话上方横幅"界面可能不是最新；签名已禁用；新消息会在恢复后发送"；恢复后提示已补齐的事件数 |
| 外部变化 | 有人直接在 GitHub 上合并或关闭、Outbox 失败、策略拒绝、对账发现偏差：以事件行呈现，相关上报项自动关闭并注明"已在 GitHub 上处理" |
| 证书将过期 / 已吊销 | 顶栏连接状态显示对应文字 |
| 未选中任何项 | 检视器提示"选中只影响这里，不会改变消息发送的上下文" |

### 2.9 键盘与可访问性

- 顶部有"跳到输入框"跳转链接；所有可点击元素都是真实按钮，有可见焦点框。
- 选中项带 `aria-current`，视图 tab 带 `aria-selected`，档位选择器是单个 Tab 停靠点、方向键漫游。
- 颜色从不单独表达含义（见 §1.1）。

## 3. 桌面端 · 设置

以全屏浮层打开，"返回工作区"回到原状态；有未保存改动时返回会先确认。

| 分组 | 页面 |
| --- | --- |
| 服务端 | 模型、档位与预算、GitHub App、沙盒与出网、危险动作策略、后台守护、通知 |
| 项目 | 每个项目一页，只列可覆盖的键：继承全局 / 覆盖；安全相关的键标"只能收紧" |
| 本机 | 设备与证书、外观 |

模型页：

- 三张卡：大脑、干活、打杂。每张卡有用途说明、模型、推理深度；被项目覆盖时注明"被 n 个项目覆盖：…"。
- "每个档位里三类模型各做什么"表（与 [architecture.md](architecture.md) 的角色表一致）。
- 保存：需要审批设备签名；保存后提示"新配置从运行中节点的下一个节点开始生效"。

配置键见 [interfaces/config.md](interfaces/config.md)。

## 4. 手机端 · 对话

- 顶部：项目切换（项目列表带"需要你"徽标）、"需要你 · n"（点击依次跳到对应气泡）、连接状态。
- 对话流规则与桌面端一致：上次查看分隔线、种类文字 + 边框、"! 需要你 · 类型"。
- "需要你"分两类：
  - 可在手机上答复的（补规格、二选一）：气泡内给快捷按钮或"回复补充"。
  - 必须在桌面完成的（签名审批）：写明"手机不能签名 · 等待桌面签名（MacBook Pro 在线 / 离线）"。升档会增加花费，也只在桌面处理。
- 输入区：可增高的多行输入框；上方显示"回复 · @上下文 · 上限 X（项目默认）"。手机发出的消息固定使用项目默认上限。
- 推送通知点开后直达对应气泡。
- 不提供：关系地图、工作树、设置、审批签名。
