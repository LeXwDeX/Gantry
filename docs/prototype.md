# 界面原型说明

> 状态：原型 v0.1（2026-10-24），**界面中全部为示例数据**。可交互原型：[Gantry 控制台原型](https://claude.ai/artifact/AFWjX1VuDkwHvxfNLC5t29)（私有链接，需要所有者分享后他人才能打开）。本文是原型的文字版规格，供 `desktop-ui` 与 `mobile` 实现时对照。

## 1. 设计原则

| 原则 | 落地 |
| --- | --- |
| 主对话是核心（D-10） | 工作区中栏默认是对话视图 |
| 配置与工作分离（D-09、I7） | 模型、档位预算、策略只在设置页；工作区只显示运行状态 |
| 工程化、现代、紧凑（D-11） | 深色石墨底、等宽字体显示编号与分支、12–13px 正文、8px 网格 |
| 无头像（D-12） | 对话不显示 agent 与用户头像；agent 气泡用边框颜色区分种类 |
| 手机只对话（D-11） | 手机端只有一个对话屏 |

视觉记号：

| 记号 | 颜色 | 含义 |
| --- | --- | --- |
| 状态点 | 蓝 `#58A6FF` | 运行中 |
| | 橙 `#F0883E` | 失败 / 自愈中 / 缺规格 |
| | 黄 `#D29922` | 等待人 |
| | 绿 `#3FB950` | 完成 / 通过 |
| | 灰 `#8B949E` | 空闲 / 未开始 |
| 气泡边框 | 橙 | 大脑 agent |
| | 蓝 | 干活 agent |
| | 灰 | 打杂 agent |
| 档位徽标 | 灰 / 蓝 / 紫 / 橙 / 粉 | Low / Medium / High / Max / Ultimate |

## 2. 桌面端 · 工作区

| 区域 | 位置 | 宽度 | 内容 |
| --- | --- | --- | --- |
| 顶栏 | 顶部通栏 | — | Logo · 项目 tab · + · 服务端连接状态 · 需要我(n) · 设置 |
| 左栏 | 左 | 约 240px | 项目信息、进行中 Issue、进行中 PR、工作树入口 |
| 中栏 | 中 | 弹性 | 视图切换：对话（默认）/ 关系地图 / 工作树 |
| 右栏 · 检视器 | 右 | 约 300px | 选中项的交付阶段、需要你决定、当前阶段 DAG、后台守护 |
| 状态栏 | 底部通栏 | — | 事件流连接、最近一条事件、运行中沙盒数 |

窄屏时三栏依次堆叠（左栏 → 中栏 → 检视器）。

### 2.1 顶栏

| 元素 | 行为 | 数据来源 |
| --- | --- | --- |
| 项目 tab | 切换当前项目；左栏、中栏、检视器随之切换 | `GET /v1/projects` |
| + | 添加项目（绑定已安装 App 的仓库） | — |
| 连接状态 | 服务端名 + mTLS 状态 | 事件流心跳 |
| 需要我 · n | 打开收件箱 | `inbox` 中 open 项数 |
| 设置 | 进入设置页 | — |

### 2.2 左栏

- 项目信息：`owner/repo`、项目名、默认档位、私有 / 公开、默认分支。
- 进行中 Issue：状态点 + `#编号` + 标题；点击在检视器中查看。
- 进行中 PR：状态点 + `#编号` + 标题 + CI 摘要（✓ / ✗ / 无 CI）。
- 工作树：分支名 + 沙盒编号；`main` 为基线；底部"+ 新建工作树"。
- 空项目显示"暂无"。

### 2.3 中栏 · 对话（默认视图）

- 用户消息：右对齐、蓝底气泡，下方时间。
- agent 消息：左对齐、深底气泡，**边框颜色 = agent 种类**；气泡下方"种类 · 时间"。
- 气泡内可带：
  - **执行计划卡**：标题 + 档位徽标 + 步骤列表（状态点、步骤、状态文字）。
  - **审批按钮**：主按钮（如"Touch ID 签名批准 merge"）+"查看 diff"。
  - **引用 chip**：`#5`、`PR #9`、分支名；点击在检视器中打开。
- 后台事件：折叠成一行（状态点 + 时间 + 摘要），不打断对话。
- 输入区：多行输入框；下方一行是 `@ 上下文`（当前选中项，默认"全项目"）、**档位选择器**（None … Ultimate，选中项用对应档位颜色填充）、`⌘↵` 提示、发送按钮。
- 视图头部显示图例："气泡边框 = agent 种类：大脑 / 干活 / 打杂"。

### 2.4 中栏 · 关系地图

- 三列：Issue（按 Milestone 分组）→ Pull Request → 工作树 / 沙盒。
- 节点卡：状态点、编号、档位徽标、状态文字、标题（工作树用等宽字体）。
- 连线：实线 = closes / 分支；虚线 = refs 或"尚未开 PR"直连；橙色虚线 = 缺规格（PR 无关联 Issue）。
- 选中一个节点：其连通分量高亮，其余节点和连线淡化；检视器显示该节点。
- 一个 PR 可连多个 Issue（closes 多个），一个 Issue 可被多个 PR 引用。

### 2.5 中栏 · 工作树

表格列：工作树、关联（Issue / PR）、沙盒、写权持有者（前台 agent / 后台自愈 / 后台 review / —）、状态。`main` 为基线行。点击行在检视器中打开。

### 2.6 右栏 · 检视器

| 区块 | 内容 |
| --- | --- |
| 头部 | 编号、类型（Issue / Pull Request / 工作树）、状态；标题；关联链（如 `#3 → #4 → PR #8 → feat/forge-app`） |
| 交付阶段 | 7 段进度条：规格、计划、实现、提出、评审、合并、关闭；已完成绿色、当前强调色、未到灰色 |
| 需要你决定 | 仅在有上报时出现：说明 + 主操作 + 查看详情 |
| 当前阶段 DAG | 节点列表：状态点、节点名、状态 |
| 后台守护 | 守护处理过的事项：事项 + 处置方式（静默自愈 / 攒到下次推送 / 上报） |

检视器**不显示模型配置**；"谁在干活"只通过对话气泡边框和节点名体现。

### 2.7 状态栏

事件流连接状态、最近一条事件、运行中沙盒数。

## 3. 桌面端 · 设置

左侧分类：服务端（模型、档位与预算、GitHub App、沙盒与出网、危险动作策略）与本机（设备与证书、外观）。原型展开的是"模型"页：

- 三张卡：打杂模型、大脑模型、干活模型。每张卡有用途说明、模型下拉、推理深度下拉（干活模型可选"随档位"）。
- "档位如何调用三类模型"表：每个档位下大脑 / 干活 / 打杂各做什么（与 [architecture.md §8–9](architecture.md#8-档位阶段与图) 一致）。
- 保存、测试连接。提供方凭据只存服务端，桌面端不保存。

配置键见 [interfaces/config.md](interfaces/config.md)。

## 4. 手机端 · 对话

- 顶部：项目切换（项目名 + 下拉）、服务端连接状态。
- 对话流：与桌面端规则相同（无头像、气泡边框区分 agent 种类、需要人时在气泡下标"需要你"）。
- 底部：输入框 + 发送按钮（触控目标 ≥ 44pt）。
- 不提供关系地图、工作树、设置、审批签名；需要审批时提示"在桌面端签名审批"。

## 5. 状态与空态

| 情况 | 表现 |
| --- | --- |
| 项目无进行中工作 | 中栏空态："这个项目没有进行中的工作"+ 新建 Issue / 导入已有 Issue |
| 未选中任何项 | 检视器提示"在对话、地图或左侧列表中选择一项" |
| 事件流断开 | 状态栏圆点变灰并显示重连中；恢复后按游标补齐 |
| PR 无关联 Issue | 地图中橙色虚线框 + 检视器"需要你决定：创建 Issue 并关联" |
