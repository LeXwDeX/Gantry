# 多工作树协作（目标设计）

> 状态：**待冻结提案**，不是现行实现。D-14、D-15 记录用户明确目标；P-83–P-86 是待契约批准的设计提案，Q-13 未确认。D-15 只记录用户目标；服务端中介与不跨树写是从沙盒只计算与工作树隔离推导出的方案约束，不是 I1 / I5 / I8 的字面规定，也不是用户另行拍板的实现机制。本轮不改实现，也不改生产契约（`docs/interfaces/**`、`docs/data-model.md`、`schemas/**`）；本文不登记新路由、枚举、事件或字段。正式接线前必须单独批准契约 PR。

本文回答三个问题：现行契约已经允许什么，目标协作增加什么，哪些边界不能越过。具体协议、端口和 UI 仍待冻结；本文只给边界、模块归属和验收用例。

## 1. 结论与边界

- **主对话统筹，不是共享执行上下文。** 一个项目仍只有一个主对话；多个任务可并行，但每个任务保留自己的 Delivery、Worktree、Workflow、Attempt、预算和范围。主对话不把多个 agent 合并成共享内存、共享会话或共享工作区。
- **协作只能经服务端中介。** 服务端中介与不跨树写是从沙盒只计算、外部文本不可信、产物先验后推和工作树隔离推导出的方案约束，不是 I1 / I5 / I8 的字面规定，也不是 D-15 另行拍板的用户机制。同项目 agent 可以只读观察、发送受限消息、阅读用户授权的跨树快照；不能直接访问其他工作树，不能跨树写，不能把消息当命令。
- **基础协作不要求 Ultimate。** 独立交付单元本来就可并行；Ultimate 仍只用于大目标自动拆分和依赖统筹（M4）。None 仍是纯问答，不创建交付单元。
- **现行契约不变。** 本文描述的目标设计须先经契约批准；M0、M1 和原终审结论不自动覆盖本扩展。

| 维度 | 现行契约 | 目标协作（提案） |
| --- | --- | --- |
| 并行 | 不同交付单元之间可并行；同一交付的状态推进由单 actor 串行，图内就绪节点按 DAG、锁与并发 / 预算闸并行 | 保留；增加受控的观察、消息和跨树只读，不引入共享执行上下文 |
| 上下文 | 每个任务独立 Delivery / Worktree / Workflow / Attempt、预算、范围 | 保留；不引入共享执行上下文或共享写工作区 |
| 用户消息 | 一条用户消息至多创建一个交付单元，`source_message_id` 幂等；多 `refs` 命中多个交付单元仍 `Ambiguous` | 保留；agent 消息是另一条通道，不改变用户消息语义 |
| 工作树写权 | 同树单写者，租约 + fence；`sandbox_ro` 读固定副本 | 保留；跨树只读，无跨树写 |
| 文件阅读 | 现行 API 只返回已投影资源，没有任意文件内容读取；跨工作树内容读取未定义 | 仅读用户授权的已发布快照，按 commit + 相对路径 + digest 固定来源；路径存在不等于授权 |
| 验证 | 各模块、各 PR 分别验证 | 增加独立组合验证；分别通过不等于组合通过 |
| 档位 | Ultimate 在 M4 做 Milestone 拆分与依赖统筹 | 基础协作不依赖 Ultimate；Ultimate 不因协作而扩大职责 |

## 2. 现行基线（不改）

以下行为来自现行契约，是本提案的地基，不是目标设计的新承诺：

- **一条消息一个交付单元。** `conversation` 的 `CreateDelivery` 以 `source_message_id` 幂等（[conversation §7.6](modules/conversation.md#76-路由表route-纯函数)、[engine §6](modules/engine.md#6-对外接口)）。`refs` 命中多个非终结交付单元时返回 `Ambiguous`，不合并执行。
- **每任务独立状态。** Delivery 拥有自己的阶段、预算与 Worktree；Workflow 的 `graph_rev` 每次改写递增；Attempt 的输入固定，状态由服务端推进。不同交付单元可并行；同一交付的状态推进由单 actor 串行，图内就绪节点仍按 DAG、锁与并发 / 预算闸并行（[engine §7.1](modules/engine.md#71-总体结构事件溯源event-sourcing--纯决策)）。
- **同树单写者。** 写权锁由 `store` 的 `worktree.locked` 事件仲裁，`fence` 取该事件 `seq`；租约过期后的旧持有者不能提交（[repo §7.6](modules/repo.md#76-写权锁)）。`sandbox_ro` 基于 `base_sha` 的独立工作区副本，不持写锁，也不指向活跃工作树。
- **沙盒只计算。** 服务端与沙盒之间只有文件、stdout 和运行时信号；stdout 是不可信自报，只用于展示（[worker-protocol §1](interfaces/worker-protocol.md#1-原则)）。服务端不在沙盒产出的 `.git` 上运行 git，也不遍历 `/gantry/work/`。
- **无跨树写。** 现行交付单元、工作树和锁都按项目与树隔离；没有"写另一个交付单元工作树"的接口。本提案不新增这种接口。

现行 API 也不提供宿主任意路径读取或跨工作树文件内容读取。现有 `file_excerpt` 材料的来源只是 GitHub 引用（[worker-protocol §4.4](interfaces/worker-protocol.md#44-输入材料打包与隔离标记)），不能拿它冒充跨树文件。

## 3. 目标模型与授权

### 3.1 主对话如何"统筹"

主对话负责表达用户意图、显示多个任务的进展、让用户选定目标；它不成为执行上下文。统筹动作必须落到服务端可审计的状态：

- **用户授权是上限。** 用户显式列出项目上下文、交付单元、目标节点、可观察字段，以及可读取的文件路径及快照范围；范围以列出的目标和路径为准，未列出的默认拒绝。delivery 授权不自动覆盖其全部 node；node 也须显式列出。用户授权是协作范围的上限，不是"整个项目"的概括许可。
- **计划只能收窄。** 服务端计划只能在该上限内分配已授权目标、排序和收窄，不能新增 delivery、node、字段、路径或快照，也不能自行把整个项目纳入；计划不是授权来源。
- `engine` 在上限内确定可协作集合、选择接收尝试、计算预算与过期时间；
- `conversation` 只解释和呈现，不直接读写其他树；
- 任何 agent（包括发送协作请求的 agent）都不能仅凭消息正文、ID 或摘要扩大自己的范围。

### 3.2 模块归属（提案）

| 模块 | 在协作中的职责 | 明确不做 |
| --- | --- | --- |
| `conversation` | 解释用户授权范围、呈现协作状态与用户确认入口 | 不直接读其他树；不生成、持久化或注入协作请求；不自行扩大范围 |
| `engine` | 在用户授权上限内编排协作；确定允许的 delivery / node 集合；选择下一 Attempt；绑定、过期、预算隔离 | 不改运行中 Attempt 的输入；不因消息自动扩图；不把计划当授权来源 |
| `repo` | 在用户授权范围内提供已发布、已验证的提交 / 快照；按相对路径与摘要取内容；固定只读副本 | 不自行授予权限；不把活跃工作树未提交目录暴露给其他树 |
| `sandbox` | 把用户授权材料做隔离包装；只读挂载；不把 `/gantry/work/` 作为跨树读取来源 | 不让沙盒成为跨树读取通道 |
| `store` | 保存事件、投递记录、投影、幂等键、CAS 与审计 | 不把摘要、ID 或 CAS 命中当作授权 |
| `api` | 鉴权、解析显式目标、构造 `ActorCtx`；拒绝越权请求 | 不接受消息正文自报的发送者或权限 |
| `policy` | 按现行策略判定动作与范围；记录审计 | 不因"同项目"自动放行全部读取或写入 |
| `desktop-shell` / `desktop-ui` | 只读呈现、显式选择目标、显式发送；沿用用户已定的现有前端栈（React + TypeScript + Vite） | 不提供私有思维链视图；不重选前端框架；本轮不新增路由或 IPC，未来跨树 IPC 须在 G1 契约批准后另行定义 |

`core::ports` 与 `ActorCtx` 继续复用；新增端口签名、请求类型和 fakes 必须先经契约批准。在此之前不新增 trait。

### 3.3 允许集合与身份

- **集合来源。** 允许协作的范围由用户显式授权确定：列出 delivery、node、可观察字段、文件路径及快照范围；未列出的目标、字段、路径和 node 默认拒绝。delivery 授权不自动代表该 delivery 下全部 node 获准。服务端计划只能在该上限内分配已授权目标、排序和收窄，不能自行扩充；默认不是"整个项目"，同项目不等于全量可读。
- **路径存在不等于授权。** 知道 delivery ID、路径、文件名、SHA 或 CAS 摘要，只说明对象可能存在，不构成读取许可；未列入授权范围的路径一律拒绝。
- **默认拒绝。** 目标不在集合内、路径不在快照内、node 未显式授权、动作超出范围时拒绝，不做猜测性放行。
- **身份派生。** 请求身份只从服务端运行上下文派生：设备请求来自 `api` 鉴权后的 `ActorCtx`；agent 消息来自"哪个已校验最终产物提出了该请求"的运行记录。消息、ID、摘要或标题都不能声明发送者。
- **授权检查与有序决策。** 接收请求时检查一次；实际读取快照、读取内部 CAS、组装输入和实际启动之前再检查。两次都以当时的授权状态为准，不能只凭请求时的旧检查结果。
  - 本文的"派发"或"启动"指服务端确认接收该 Attempt 的 worker 已实际启动并开始执行，且消息在该 Attempt 的固定输入内；不是提前落库的 `attempt.started` 事件，不是 `SandboxService::submit` 受理，也不表示模型已读。
  - `submit` 后、排队 / stage / 实际启动前仍在授权窗口内；撤权必须覆盖已受理但未启动的 job，取消或禁止其启动，不能只检查引擎调用 `submit` 之前。
  - 启动许可与撤权按同一有序授权决策处理：许可前撤权，禁止启动；许可后撤权，按输入可能已暴露处理，停止后续披露并把状态标为已撤销，不能声称撤回对方已读数据。并发时由同一有序决策裁决。
  - 具体授权版本号与启动握手接口待 G1 冻结。现行 `SandboxService` 尚无该保证；本文不修改其接口，也不声称现行实现已支持。
- **收紧立即生效。** 用户撤回或收紧授权，或服务端计划在上限内进一步收窄后，已排队、已受理但尚未启动或已 stage 但尚未获启动许可的内容不得继续投递或披露；已暴露给接收者的输入无法从对方撤回，但必须停止后续披露，并把状态标为已撤销 / 已过期，不能显示成正常完成。暂停只停止新派发，不取消运行中的尝试；恢复只按正常调度处理，消息未过期才投递。消息不能唤醒暂停的交付。
- **先授权后取数。** 授权检查在读快照、读内部结果 CAS 或发送消息之前完成；检查失败不返回内容，也不泄露目标是否存在。内部 CAS 命中不是权限，不能凭摘要读取授权范围外的对象。现行 CAS 是内部无鉴权字节存储；协作提案要求调用方 `engine` / `api` 在 `open` / `stat` 前校验同项目、用户授权与已发布快照映射，不给沙盒直接入口，不把 digest 当权限；未授权对外与对象不存在同样不确认。
- **共享面。** 共享契约或共享文件必须有唯一负责人和固定版本；重叠文件范围要在用户授权上限内由服务端计划显式协调。协调只安排各树负责人在自己树内修改，不产生跨树写权限；默认不写共享树，也不默许两个任务同时改同一文件。

## 4. 只读观察

观察只返回结构化状态、采样进度和用户授权范围内的可公开摘要，不返回原始执行现场。

| 可观察 | 内容 | 可信度 |
| --- | --- | --- |
| 交付状态 | 阶段、`stage_status`、`level_effective`、关联 Issue / PR 的已有快照 | 服务端投影 |
| 图与节点 | `graph_rev`、节点状态、是否被替换、当前 Attempt | 服务端投影 |
| 尝试 | Attempt 状态、失败码、结果引用、服务端观测的起止时间 | 服务端观测；结果是 CAS 引用，不等于已审查 |
| 进度 | `attempt.progress` 的采样 | **agent 自报**，只展示 |
| 摘要 | 已校验产物中的可公开摘要 | 不可信文本；来自产物，未经新授权 |

每条观察必须让接收者能判断来源与新鲜度：

- **来源**：delivery / worktree / attempt，以及产生该状态的运行上下文；
- **时间**：服务端接收时间，不采用 agent 自报时间；
- **序号**：事件 `seq`；跨恢复边界时同时给出 `log_epoch`；
- **图版本**：`graph_rev`；
- **尝试**：实际 `attempt_id`，不是节点当前指针的猜测。

`log_epoch` 变化表示事件日志恢复过，客户端应丢弃旧缓存并全量重同步；`seq` 缺口表示可能丢事件，应重新取快照。观察可以落后，但必须明确标记过期，不能把旧状态显示成当前状态。

每次读取观察都按当时的授权检查；范围收紧后，已缓存但未展示的内容不再披露，已展示的内容标注来源与时间，不能继续当作实时状态。

**禁止**：私有思维链（chain-of-thought）、完整终端 / stdout、凭据或密钥、宿主路径、其他项目内容、未授权快照的文件内容。自报不是可信事实：它不驱动状态机、不决定成败、不改变权限或预算；界面要标注"agent 自报"，不能标注成"已确认"。

## 5. 消息：下一尝试投递

### 5.1 消息不是命令

agent 之间的消息是**下一次尝试投递的保守提案**，不是用户已批准的结论，也不是对运行中进程的控制信号。它最多成为下一次尝试的输入材料；是否采纳由接收方模型在自身任务中判断，任何动作仍走现行 `policy` 与 Forge Outbox。

发送侧约束：

- 发送 agent 只能在**正常完成且校验有效的最终产物**里提出请求；超时、失败、取消、部分产物不得提出。
- 服务端在沙盒停止后读取最终产物，不从运行中的 stdout 抓取；stdout 只用于展示，不解析成命令。
- 请求必须声明目标 delivery / workflow / `graph_rev` / node 和消息正文，且目标在用户授权范围内；目标不明确或越界就拒绝。
- 正文一律是 `UntrustedText`；不能伪装成 `user` 输入、`supply_spec`、settings、审批、合并控制，也不能写成"已批准"。

### 5.2 绑定与投递语义

接收目标固定为 delivery / workflow / `graph_rev` / node，且须在用户授权范围内。服务端只按原节点在原 `graph_rev` 上的正常调度，绑定**下一次尚未准备输入的 Attempt**；不为消息创建 Attempt，也不插队：

1. 记录实际 `attempt_id` 和该次输入的摘要；
2. 组装输入之前再次检查授权；范围已收紧或目标已变化时，绑定作废，不装入；
3. 将消息作为不可信材料装入该次输入；`SandboxService::submit` 受理不等于启动许可，`submit` 后到实际启动前若撤权或收紧，按 §3.3 的有序决策取消或禁止启动；
4. 服务端确认接收该 Attempt 的 worker 已实际启动，且消息在该次固定输入内，才可称"已投递"。

当前 Attempt 正常结束不等于目标终结。若原节点、原 `graph_rev` 还有下一次正常调度，消息可绑定该调度创建的 Attempt；若没有，就保持有限等待后过期，不因为当前 Attempt 结束立即过期，也不把消息转成新的执行入口。

已经装进某次输入的文本无法从接收者处撤回；发现越权或范围收紧时，服务端停止后续披露，把投递标为已撤销 / 已过期并审计，不能假装没有发生。

| 阶段 | 记录 / 含义 | 不能声称 |
| --- | --- | --- |
| 已持久化 | 消息已落库，带幂等键 | 目标已接受 |
| 已绑定 | 服务端选定下一次正常调度且尚未准备输入的 Attempt，记录 attempt 与输入摘要 | 模型已看到 |
| 已装入输入 | 材料已进入该次输入包 | 模型已理解 |
| 已启动（可称"已投递"） | 服务端确认接收该 Attempt 的 worker 已实际启动，且消息在该 Attempt 的固定输入内；证据是启动确认与输入摘要 | 提前写下的 `attempt.started` 事件、`SandboxService::submit` 已受理，都不等于已启动；模型已读或已执行 |
| 模型已读 / 已执行 | 没有可靠的服务端证据 | 不得作为状态或验收依据 |

"已投递"只是运维 / 展示用语，不表示模型已读、已理解或已执行。若模型在产物中声称读过，这仍只是不可信自报。现行契约可提供 `attempt.started` 事件和 `SandboxService::submit` 受理，但二者都不足以证明 worker 实际启动；所需的启动确认与授权握手是目标契约，待 G1 冻结，未接线前不得用现行事件名冒充该语义。

### 5.3 不注入、不静默转投

- 目标 Attempt 正在运行：**不注入**，等原节点在原 `graph_rev` 上的下一次正常调度；不修改其输入。
- 目标 node / workflow / delivery 已终结、节点已被替换、`graph_rev` 已变化：**不静默转投**；以可见的过期 / 拒绝结束。当前 Attempt 正常结束不是目标终结：原节点在原 `graph_rev` 上仍有下一次正常调度时可绑定，没有时有限等待后过期。
- 没有下一次正常调度（没有可绑定的后续 Attempt）：保持有限等待，然后过期；不因消息自动重试、唤醒暂停的交付、创建节点、扩大预算、插队或自建 Attempt。正式轮次结束或没有正常调度时，消息不能成为新的执行入口。
- 授权在组装输入和实际启动前再次检查；`submit` 已受理但未启动、或已 stage 但尚未获启动许可的 job 也受撤权 / 收紧约束，必须取消或禁止启动，不能只检查调用 `submit` 之前。范围已收紧或已撤销时，尚未启动的内容不再投递，状态可见。
- 暂停只停止新派发，不取消运行中的尝试；恢复只按正常调度处理，消息未过期才投递。消息不能唤醒暂停的交付，也不因暂停 / 恢复自动重发。
- 超时必须终结并可见；不能无限挂起，也不能把"等待中"显示成"已投递"。
- 失败或取消不自动转发产物，也不自动重发；重试必须是新的显式请求，不改旧 Attempt。

### 5.4 幂等、恢复与限额

- **幂等键**：发送 Attempt + 发送方本地请求 ID。同键同内容返回同一条记录；同键不同内容拒绝。
- **重启恢复**：绑定是持久的，绑定到哪个 Attempt 就只处理哪个 Attempt；恢复不得重投另一个 Attempt。无法继续时过期并可见，不能偷偷换绑。
- **失败 / 取消**：当前 Attempt 失败或取消不自动转发产物，也不自动重发；该 Attempt 上等待的消息不转投后续 Attempt，按过期处理。重试或再次投递须新的显式请求，不改旧 Attempt。
- **限额**：数量、字节、期限和材料预算都有限；具体数值与配置键由契约批准时确定，本文不新增默认值或配置键。
- **洪泛**：超限时拒绝或背压，不能拖垮调度；拒绝原因对发送方可见，但不泄露未授权目标。

消息正文可以让接收方读到，但永远不能凭正文获得权限、触发设置写入、代表用户批准或触发合并。

## 6. 跨树文件只读

### 6.1 允许的来源

只允许读**同项目、用户显式授权、已发布且由服务端验证产生**的提交 / 快照。本文的"发布快照"（提案）指 `repo` 已生成、校验并登记为不可变引用的提交或快照；它不等于已推送、已通过测试或可合并。跨树来源仅限已发布快照；服务端内部结果 CAS 不是跨树来源，不能凭摘要跨树读取。路径存在、知道文件名或摘要不等于授权。

来源必须固定为：

```
delivery / worktree + commit SHA + 相对路径 + blob / content digest
```

读取请求只能指定用户授权的快照和相对路径，不能指定宿主路径、绝对路径或任意镜像对象摘要。

### 6.2 禁止

- 运行沙盒的 `/gantry/work/`；
- 其他活跃工作树中未提交、未发布的目录；
- 宿主任意路径或目录浏览；
- `.git/` 内部对象、hooks、config 或任何凭据、secret 材料；
- 跟随 symlink 或 submodule 进入其内容；
- 执行读到的文本（脚本、宏、模板、命令都不执行）；
- 把 SHA、CAS 摘要、delivery ID 或消息当成能力凭证；
- 通过摘要枚举镜像仓中的任意对象。

### 6.3 读取规则

- **先授权再取**：权限检查在读取之前；没有授权不返回字节，也不确认对象是否存在。读取内部结果 CAS 也受同一授权检查；CAS 命中或知道摘要不是权限。现行 `Cas::open` / `stat` 是内部无鉴权字节存储，协作提案要求调用方 `engine` / `api` 在调用前完成同项目、用户授权与已发布快照映射校验；不给沙盒直接入口，不以 digest 当权限，未授权对外与不存在同样不确认。
- **路径存在不等于授权**：只按用户授权的路径与快照范围读取；同项目内存在但未列入授权的路径一律拒绝，不因目录存在、文件名常见或摘要匹配放行。
- **路径闭合**：拒绝 `..`、绝对路径、NUL、控制符和越出快照根的路径；只按相对路径解析。
- **符号链接 / 子模块**：不跟随；返回明确的"不可读 / 缺失"，不返回链接目标内容。
- **大小与截断**：有大小上限；截断必须带元信息；缺失必须明确失败，不能静默返回空内容。
- **固定副本**：`sandbox_ro` 读固定副本，不读活跃工作树；跨树读取由服务端返回受限材料或只读内容，不把其他工作树挂载进沙盒，也不提供宿主文件句柄。跨树读取不改变任何工作树状态。
- **发布不等于通过**：发布快照只表示来源固定，不表示测试通过或可合并；读取者不能据此宣称验证通过。

ref 的保留、回收与审计只给要求：固定来源在验证和审计需要时必须可寻址；回收不能悄悄改变来源；来源消失时明确报缺失。本文不设 TTL，也不把保留期写成已定事实。

### 6.4 现行契约缺口

现行 `file_excerpt.source` 只允许 GitHub 引用（`owner/repo#N` 或 `owner/repo#N/<item_id>`），见 [worker-protocol §4.4](interfaces/worker-protocol.md#44-输入材料打包与隔离标记)。不能把跨树来源伪造成 `owner/repo#N/1`，也不能塞入未定义的 `source` 形状。正式增加 `source` / `kind` 必须走版本化契约，并同步冻结 schema 与 fixture；在此之前不新增枚举值。

## 7. 独立组合验证

组合验证回答"选定的几个任务放在一起是否真的能工作"，不是各任务自检的汇总。

一次验证记录至少绑定：

- 选定任务的固定候选 SHA；
- 基线 SHA；
- 契约版本（含协议 / schema 版本）；
- 组合顺序；
- 组合后的结果树摘要。

规则：

- **编排与证据归属（提案）。** `engine` 编排组合验证；`repo` 提供固定的候选 / 基线源；`sandbox` 在独立临时副本上运行验证，不复用参与树的工作区；`store` 持久化证据与审计。具体端口、记录形状与保留期限待 G1 冻结。
- 前后端分别通过**不等于**组合通过；必须实际按组合顺序运行。
- 失败或冲突回到各自负责人处理，不跨树修复，不把别人的工作树当补丁目标。
- 任何来源的 head、base 或契约版本变化，都使组合证据过期，必须重验。
- **合并门禁（仅限参加目标）。** 对用户明确列入组合交付的目标，合并前缺失、失败或过期的组合证据阻止推进或写入合并动作；该要求不扩展到未参加协作的既有 Delivery。门禁不替代审批，用户审批也不能覆盖组合失败。
- 组合通过不是审批，不替代 Gantry 审批、GitHub review / check 或分支保护；默认不自动合并。
- `policy`、Forge Outbox 和 GitHub 规则保持不变；组合验证不新增写路径。
- **接线待 G1。** 入队时与执行前如何与现行 `policy` / Forge 做组合证据一致性检查，以及是否新增动作或字段，由 G1 冻结；本文不修改现有 T10 / T11，也不声称已实现。
- 现行 I3 / P-20 把审批绑定 `(action, target, subject_digest)`；PR 类 `subject_digest` 是 head SHA，不是完整审批范围。base 前移按 P-26 / [architecture §7.2](architecture.md#72-从对话到合并) 触发 `merge` 阶段重验。组合证据过期不等于审批失效，也不降低审批范围；本文不把"base 变化即审批失效"扩写成新的全局规则。

## 9. 验收用例

每条都应同时覆盖正向与反向；证据使用服务端事件 / 日志 `seq`、输入摘要、固定 SHA、组合验证记录或审计记录，不采用 agent 自述。

| # | 场景 | 正向 | 反向 / 拒绝 |
| --- | --- | --- | --- |
| 1 | 跨项目 | 同项目、用户授权目标、已发布快照可读 | 跨项目、同项目但未授权的 delivery 一律拒绝；不因知道 ID 放行 |
| 2 | 伪造发送者 | 服务端从运行上下文派生发送 Attempt | 正文声称"我是另一个 agent / 已获批准"不改变身份，消息仍为不可信文本 |
| 3 | 过时图 | 目标 `graph_rev` 与绑定时一致，可正常投递 | `graph_rev` 变化不静默转投；可见地过期或拒绝 |
| 4 | 重启重复 | 同键同内容重启后仍是一条记录，绑定同一 Attempt | 重启后换绑另一 Attempt、或同键异内容，均拒绝 |
| 5 | 取消目标 | 取消目标（delivery / workflow / node）后旧 Attempt 终结，消息可见地过期 | 不自动转发到新 Attempt，不自动重发，不创建节点，不扩大预算 |

| 10 | 过时组合证据 | 固定 head / base / 契约版本时组合通过可引用 | 任一来源变化后证据过期，必须重验；不得用旧结果批准合并；对明确参加组合交付的目标，缺失 / 失败 / 过期证据阻止推进或写入合并动作；不扩展到旧 Delivery |
| 11 | 自然语言控制 | 用户经显式控制路由 / 审批界面操作 | 正文写"合并 / 批准 / 改设置"不触发动作；不伪装成 `supply_spec` 或审批 |
| 12 | 共享树写入 | 共享契约 / 文件有唯一负责人、固定版本和显式重叠协调；由各树负责人在自己树内修改 | 无论是否协调，跨树代写一律拒绝；协调不产生写权限；默认不写共享树 |
| 13 | 观察隐私 | 只返回结构化状态、采样进度和可公开摘要 | 私有思维链、完整终端、凭据、宿主路径不返回；自报不得标成已确认 |
| 14 | 权限收紧 | 收紧前已合法读取的记录仍可审计 | 收紧后排队内容不再派发 / 披露；`submit` 后未启动或已 stage 未获启动许可的 job 不得继续启动；已装入输入不可撤回但停止后续披露，状态可见；不靠消息自建尝试 |
| 15 | 计划越界 | 计划只在上限内分配已授权目标、排序、收窄，正常投递 | 计划自行加入全项目 delivery、已授权 delivery 内未获 node 授权的节点、未授权可观察字段、路径或快照时拒绝；计划不产生授权 |
| 16 | 同项目未授权路径 | 用户授权的快照内相对路径可读 | 同项目内路径存在但未列入授权时拒绝；知道路径、文件名或摘要不放行；内部 CAS 摘要也不是跨树读权限 |
| 17 | 当前尝试正常结束 | 原节点在原 `graph_rev` 上有下一次正常调度时，绑定该调度创建的 Attempt | 当前 Attempt 正常结束不使目标过期，也不使消息转投；失败或取消不转投后续 Attempt；没有下一次正常调度时有限等待后过期，不由消息创建 Attempt 或插队 |
| 18 | `submit` 后启动前撤权 | `submit` 已受理、worker 尚未实际启动时撤权，job 取消或禁止启动，消息可见地过期而不投递 | 不能只检查调用 `submit` 之前；不把 `submit` 受理或 `attempt.started` 事件当成已启动 / 已投递；不因已 stage 而继续启动；不声称模型已读 |
| 19 | 已装包未获启动许可 | 装入输入后、启动许可前撤权，停止启动，标为已撤销并记录可能已装入 | 不声称撤回已装入内容或对方已读；不以"尚未启动"掩盖已暴露；不再披露；不自动重发或转投 |
| 20 | 各树通过但组合失败 | 各树自测通过、组合运行失败时，失败回到负责人，证据可见 | 用户审批不能覆盖组合失败；缺失 / 失败 / 过期的组合证据阻止推进或写入合并动作；只对明确参加组合交付的目标生效，不扩展到旧 Delivery |
| 21 | 暂停 / 恢复 | 暂停只停新派发，运行中尝试跑完；恢复只按正常调度，消息未过期才投递 | 消息不唤醒暂停交付；不因暂停取消运行中尝试；不自动重发；不转投已取消 Attempt |
| 22 | 内部 CAS 读取 | 同项目、用户授权、已发布快照映射齐全时，`engine` / `api` 在 `open` / `stat` 前校验后读取 | 仅知道 digest、跨项目、未授权或未映射快照一律拒绝；对外与不存在同样不确认；不给沙盒直接入口；digest 不是权限 |

桌面端约束作为验收的一部分：沿用用户已定的现有前端栈（React + TypeScript + Vite），不重选型；状态管理库仍待决（OQ-U1）。本轮不新增路由或 IPC，未来跨树功能须在 G1 契约批准后另行定义，不能靠既有路由实现；现行白名单不变。不增加私有思维链视图；只读观察和显式发送入口都须标明来源、时间与可信度。
