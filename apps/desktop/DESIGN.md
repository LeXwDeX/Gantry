# 桌面前端设计与演示边界

## 验收依据

视觉与交互以 `../../docs/prototype.md`、`../../prototype/Main.dc.html`、`../../prototype/Settings.dc.html` 为准，不重新设计。协议与安全规则以 `../../docs/interfaces/api.md`、`../../docs/data-model.md`、`../../docs/interfaces/config.md`、两份桌面模块规格为准。原型的运行时和演示逻辑不直接复用。

用户已确认 React + TypeScript + Vite。只修改 `apps/desktop/**`，不修改后端或共享契约，不自动提交。

## 视觉约束

- 工作区占满窗口。顶栏 44px；左栏约 240px；中栏弹性；检视器约 300px；底部状态栏。各栏内部滚动，输入区保持可见。
- 900px 及以下三栏依次堆叠，整页滚动，不产生页面横向溢出；表格和关系地图可在各自容器内滚动。
- 底色 `#0E1014`，面板 `#111418`，气泡与卡片 `#151920`，深层底色 `#0F1216`，分隔线 `#22272E`，控件边框 `#2A3038`。
- 正文 `#E6E8EB`，次要文字 `#A9B1BA`，弱文字 `#8B949E`。运行蓝 `#58A6FF`，需要你黄 `#E3B341`，通过绿 `#3FB950`，失败及缺规格橙 `#F0883E`，空闲灰 `#6E7681`。
- Inter 配随包的 Noto Sans SC 中文回退，正文 12–13px；编号、分支、时间、摘要用 JetBrains Mono。字体随包，无远程字体请求。中文使用字形范围分片按需加载，完整资源约 4.49 MB；三种字体的许可随构建输出到 `FONT-LICENSES.txt`。
- 大脑紫 `#A371F7`，干活青 `#39C5CF`，打杂灰 `#8B949E`。气泡为 2px 完整边框并显示种类文字，无头像。未知种类为中性灰。
- 设置为全屏浮层，不卸载工作区。左导航约 200px，内容最大宽 980px，三张模型卡间距 12px。审批为右侧 540px 抽屉。

## 续作范围与入口

本轮目标是完整可交互模拟前端，覆盖设置全部菜单、六类项目覆盖、连续问答和任务、工具活动、公开执行摘要、执行 DAG 与尝试详情、只读预算及跨视图控制。逐项验收见 [VERIFICATION.md](VERIFICATION.md)。

- 设置继续使用现有全屏浮层、左侧分组和紧凑表单。模型页保留三类模型布局；其余资源只列已有契约字段。显示继承、校验、脏状态、预览、模拟应用与回读；切页和返回均保护未保存草稿。
- 对话的临时生成区紧贴所属 agent 气泡。工具活动以紧凑列表显示，详情按调用折叠；公开摘要始终标为「模拟执行摘要」，可展开，状态更新不重置展开状态。所有生成状态有文字，完成后正文按正式 Message 形状结算。
- 「查看执行图」从计划卡和检视器打开同一工作流详情，保留原工作区与输入上下文，返回恢复焦点。依赖图只读；节点按钮可键盘选择。节点详情列尝试、失败、用量与进度。窄屏依次堆叠图、节点和预算，图自身可滚动，不缩小整张桌面画布。
- 预算只展示已有维度、单位、上限和消耗，不提供追加规则。修订以 `graph_rev` 和 `superseded_by` 展示，不宣称能读取不存在的历史快照。
- 开发模式提供可见场景选择、重置和回放入口。使用有限确定性脚本，不解析用户自然语言为配置或控制命令；任务控制只来自显式按钮。

所有正式实体仍通过 `IpcAdapter` 消费。演示增量、工具和摘要由独立演示适配边界提供，不加到正式 Message、Card、事件或 IPC 字段中。组件不能读写夹具或直接联网。

## 演示隔离

开发场景统一拥有消息、交付、工作流、尝试、预算、工作树和收件箱事实。各视图不各存一套模拟状态。脚本使用稳定标识和可控时间，重置、卸载、取消必须清理计时器，跨项目事件写回原项目。

本轮允许「模拟应用设置」「模拟批准」「模拟配对」，仅改变场景内存，不生成真实签名、凭据、证书，不做网络写入。示例标记在工作区与浮层始终可见。正式构建不加载场景适配器，也不静默回退到示例模式；审批模拟分支由 `import.meta.env.MODE` 在构建期折叠，正式 JavaScript 产物不包含模拟批准文案或方法引用。

凭据输入明确标注「仅测试占位值，勿输入真实凭据」。提交准备后清空，不进入全局状态、界面持久化或日志；模拟回读只提供已设置标记。

共享机器可读 schema 尚未交付。前端类型暂按已有文字契约转写并注明来源，不增路由或协议字段，不冒充自动生成类型。模型枚举和推理深度仍从 `settings.catalog` 读取。通用 schema 表单与正式 Mock API 联调在共享 schema 到位后完成。

类型检查、构建、纯逻辑与交互测试通过；1440×900、390px 窄屏实际运行与截图已覆盖关键页面；独立评审由主力在集成后组织。真实后端、Tauri 原生安全边界、Touch ID / Windows Hello、系统通知与安装包不由浏览器替身测试宣称通过。


## 本轮已定实现

- `App` 是唯一浮层编排点：设置、收件箱、审批单、执行图互斥；执行图从计划卡或检视器打开，关闭后由统一的 returnFocus 回到触发元素。场景工具在 unpaired、error 阻塞页也保留，因此阻塞状态下仍能重置。
- 工作区左栏分组可折叠，最近完成同样保留折叠与计数；宽度和折叠状态由 `Prefs.layout` 决定，外观页保存成功后通过 `onPrefsChanged` 立即更新根节点 CSS 变量与折叠类，不持久化到浏览器存储。
- `Inspector` 在缺少工作流时按交付懒加载当前图；加载完成前入口禁用，避免“有按钮但无内容”。执行图内节点可用 Tab 或方向键选择，尝试、失败原因、用量、结果编号和只读预算都来自控制器缓存。
- 场景重试追加新的工具调用标识与新尝试，旧失败调用和旧尝试不被改写；结束摘要只展示公开的执行说明。
- 审批单把生产签名和模拟操作分开：生产按钮仍是原 `approvalSign` 路径，场景中禁用并 fail closed；“模拟批准（不生成签名）”“模拟拒绝”通过 `Simulation` 独立方法修改内存，必须同时满足 approver、live、pending、head 一致和确认窗口有效。模拟完成后刷新同一 `approvals` 状态，供收件箱、检视器和对话同步。
- 配对页在场景中明确标注固定测试确认码，可注入一次配对预检失败后重试；配对串在开始前清空。真实外壳仍走原 `pairingBegin`/`pairingConfirm`。
- 项目覆盖、全局设置、设备、外观都使用共享 `GuardedWrite` 生命周期：本地校验、预览、模拟提交、回读；冲突、失败和页内未保存草稿都有明确恢复入口。

## 生产隔离说明

`src/ipc/index.ts` 仍只在 scenario 构建动态加载 `scenario/adapter`，正式构建没有场景适配器、没有示例回退；审批模拟 UI 的条件使用构建期 mode 常量，正式 `dist/assets/*.js` 经产物扫描不含 `simulateApproval`、`模拟批准` 或 adapter chunk。其他共享组件仍保留安全的正式/演示双路径源码，但正式产物只保留可达的生产路径；场景产物保留独立 adapter chunk。
